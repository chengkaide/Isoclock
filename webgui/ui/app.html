④ 普通铅校正
%

桌面版界面上这一格写作 Ɛ(%)，源码里的变量是 excess_V （= 这里填的数 ÷ 100），桌面版默认 3，本页默认与之相同。

它是什么：除了"数计数"本身的统计波动之外，还会有的那部分额外分散。 同一台仪器反复测同一样品，分散往往大于计数统计所预期的量 —— 来源是剥蚀效率波动、 气溶胶传输不均匀、标样与样品的基体差异、标样不匹配、数据处理软件的拟合残差等。 只用计数误差会低估不确定度，Ɛ 就是用来补这一块的。

它怎么用：以平方和（正交相加）并进每一个年龄的相对误差 ——
  年龄的相对误差 = √(内部相对误差² + Ɛ²)
  年龄的误差 = 年龄 × 上面那个相对误差
代码依据是 Isoclock2.0.py 第 397 / 399 / 401 行，三处是同一个模板：
  sqrt(pow(date_all[3][i]/(date_all[2][i]*f206_238), 2)
        + excess_V*excess_V)
其中 date_all[3] 是该比值的 2s，除以比值本身就是内部相对误差。

它不影响年龄本身。年龄是 ln(比值+1)/λ，与 Ɛ 无关； 把 Ɛ 改大改小，年龄一个数都不变，所有 ± 跟着变大变小。 只有 rho（相关系数）列也跟着动，因为它的公式里也用了 Ɛ。

三条必须知道的口径问题：
① 内部相对误差用的是表里的 2s，也就是 2σ，而程序把 Ɛ 直接与它 平方相加 —— 相当于把 Ɛ 当成 2σ 同量级的量。你没量过 Ɛ 是 1σ 还是 2σ 的话， 这里其实是混着用的，报出去的不确定度到底是几 σ 要自己心里有数。
② ²⁰⁷Pb/²⁰⁶Pb 年龄（第 24 列）的误差（第 25 列）不含 Ɛ：它是 solve76(R76+d1) − solve76(R76)，只由该比值自身的误差传播而来。 所以同一行里四个年龄的误差口径并不一致，横向比较要小心。
③ Ɛ 调大会让 MSWD 变小：每个点的误差都变大，点与点之间就显得更一致了。 当 Ɛ 远大于内部误差时，各点误差趋于同一比例，MSWD 会趋近 0， 加权平均退化成普通平均 —— 不要用调 Ɛ 的办法去"改善"一致性， 那是把不确定度人为灌水换来的表面一致。

⑤ 年龄层

NIST610 / 612 / 614（也认 SRM 写法）。留空表示不算。 注意：这个名字在整批数据里必须出现 ≥2 次，否则原实现的异常分支会让 系数静默变成 0 —— 网页版照原样复现了这一点。

这个网页版是什么，以及它不做什么

    
它把 Isoclock 桌面版（Isoclock2.0.py）的两段核心数值计算——Thermo 数据的
      读取/积分/还原与标样校正与年龄计算——原样搬到了浏览器里，界面重写，
      数字一个不改。设计目标是单文件、离线、零依赖：把这一份 HTML 拷到任何地方双击就能用，
      不上传数据、不联网。唯一例外是可选的"IsoplotR 谐和图"标签页
      —— 那一页要联网（点了它的按钮才下载），其余全部功能离线可用。


    
结果可信到什么程度

    
同一批数据下，网页版的输出与桌面版逐位相同（bit-for-bit，包括浮点最后一位）。
      这不是估计，是跑出来的：409 项 Node 端自动比对
      （14 套 webgui/test_*.js：数值内核、
      Thermo/Agilent 解析、积分窗口、两个 CSV 的逐字节输出、
      年龄层 51 列 × 19 组参数、20 项 Agilent 端到端、
      47 项 Thermo 兼容读取、
      63 项 质量统计、
      50 项 报告组装、
      22 项 内置真实示例数据、
      73 项 IsoplotR 接入层）
      ＋56 项本页面内自检（走的是真按钮那条路）。

      上面这些数不是手写的：docs/make_badges.py 每次都会把测试真跑一遍，
      连逐套的项数也一起核，对不上就让 CI 红。真正手写的是这一句解释。

      唯一一处曾经对不上的地方是 exp / log：宿主 C 运行时与浏览器的
      实现允许差 1 ULP，实测约有 9% 的 Math.exp 调用与正确舍入不同。
      网页版因此自己实现了正确舍入的 exp/log（fp.js），
      顺带让结果不再依赖运行平台——同一批数据在任何浏览器、任何系统上都是同一串数字。


    
保留的原实现缺陷（没有偷偷修）

    
    
      
  • Age76Pb 的割线迭代写错了：循环条件里的 Rap 从未更新，
        收敛判据一旦为真就永远为真，于是实际是固定迭代 10 次。在 1.5–2.2 Ga 区间会
        造成最大约 +35 Ma 的偏高；比值恰在起点附近时甚至直接返回 0 岁。
        默认已提供收敛修正（左侧⑤勾选框），取消勾选则逐位回到桌面版数值。
    • 
      
  • 微量元素系数会静默归零：所选 NIST 标样在整批数据里出现 0 次或恰好 1 次时，
        原代码内部抛异常并被 except 吞掉，系数直接变 0。已如实复现。
    • 
      
  • 204Pb 路径会除零：某些数据下 204Pb 计数差为 0，原代码不判。
        网页版在界面上把这种行标成 NaN 并给出提示，
        数值本身仍与原实现一致。
    • 
      
  • Hg 校正恒为零：原实现里 202Hg 通道参与了流程但结果始终是 0。
    • 
      
  • 拼写笔误：输出列名 232Pb_232Th，以及末位缺 s 的
        …Corrected isotop（四条校正路径各一版：
        204／207／208／Cal 204Pb）
        照抄保留，以免下游脚本按列名匹配时对不上。勾选"修正列名笔误"可换成正确写法。
    • 
      
  • 外挂误差 Ɛ 的三处口径不齐：桌面版界面上写作 Ɛ(%)，默认
        3%；它以平方和并进各年龄的相对误差 —— 只改误差，不改年龄。但
        ① 内部相对误差用的是比值的 2s（即 2σ），Ɛ 直接与它平方相加，
        等于按 2σ 同量级对待，严格说混了置信水平；
        ② ²⁰⁷Pb/²⁰⁶Pb 年龄的误差不含 Ɛ，同一行四个年龄的误差口径并不一致；
        ③ Ɛ 调大会让 MSWD 变小，不能用它去"改善"一致性。
        左侧④那一格旁边写了完整说明。

  • 支持 Thermo 与 Agilent 导出的 CSV（左侧③选择仪器）。
        Element 的 .fin 是专有二进制，请先用桌面版转一次。

        认出来的文件在列表里打「兼容」标记。标准格式文件走的仍是原来那条路径

怎么验证

    
想自己验一遍：在地址栏后面加 #selftest 打开（变成
      file:///…/isoclock.html#selftest），页面会自动用一份合成数据跑完整条链，
      把每一项检查写在"日志"页，并挂在 window.__selftest 上、把页面标题改成
      SELFTEST-OK [通过数/总数] 或 SELFTEST-FAIL …，
      方便无头浏览器读取。

    
这一份单文件是怎么来的：源码在 webgui/ 下（src/ 是数值模块
      ——每个模块都跟桌面版逐位比对过；ui/ 是界面与自检；
      test_*.js 是上面那一批逐位比对，项数与套数由脚本每次实跑后核对，
      所以这里不写死数字）。本文件由
      python webgui/build_ui.py 拼成，改动请改源头再重新构建，
      不要直接编辑本文件。构建脚本自己也会检查：占位符有没有残留、模块有没有漏、
      顶层有没有重名——重名这一条是踩过坑的（几个模块合并进同一个 script 块时，
      同名的顶层函数会互相覆盖），所以重名必须逐个登记理由才能通过。

    
手上的这一份是哪一版：页脚左下角写着构建时间与源码指纹，
      它在 build_ui.py 最后一次运行的输出里也打印同一串（"源码指纹：…"），
      两边对上就是同一版。想看得更细：按 F12 打开控制台，输入
      window.__build 可看到构建时间、源码指纹 id
      与每一个模块各自的指纹；同样的源码每次构建都会得到字节相同的文件，
      所以指纹一致就意味着内容一致。
