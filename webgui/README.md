# webgui —— Isoclock 网页版

把 Isoclock 的两段核心数值计算（Thermo 数据的读取/积分/还原 + 标样校正与年龄层）
移植到浏览器，做成**一个能双击打开的单文件 HTML**：不装 Python、不联网、
可邮件直接发给同行。

> **当前状态：已完成。** 交付物是 `webgui/isoclock.html`（约 826 KB，单文件、零依赖）。
> 同一批数据下，它的输出与桌面版 `Isoclock2.0.py` **逐位相同**
> （bit-for-bit，含浮点最后一位）——标准格式的 Thermo 文件走的就是这条路径。
>
> 验证规模：**439 项** Node 端比对（14 套）+ **62 项**页面内自检，全绿。
> （这两个数是**实跑出来的**，真源是 `docs/make_badges.py` 与产物页面的 `#selftest`；
> 落地页上的徽章引的就是它们。改完测试请跑一次 `python docs/make_badges.py`。）
>
> 文件之所以有 826 KB，是因为里面**内嵌了 49 个真实的 iCAP Qtegra 导出**
> （明文 1.66 MB，gzip 后 338 KB，base64 后 451 KB），作为默认示例 ——
> 开箱就能拿真数据跑一遍完整流程，而不是只看合成出来的假计数。
> 生成方式、脱敏规则、以及**为什么比源目录少一个文件**，见下文
> 「内置的真实示例数据」一节。
>
> 支持 **Thermo 与 Agilent** 两种仪器导出（Agilent 的样品名来自清单文件，见下）。
> 另外还能**导出 HTML 批次质量报告**（标样 QC / 样品汇总 / 异常清单 / 判据出处，
> 见"质量报告"一节）——这一块是网页版**新增**的，原程序不做归组统计。

## 为什么是单文件离线

| 方案 | 问题 |
|---|---|
| Streamlit / Dash | 要装依赖、要起服务，分享给别人对方也得装 |
| 纯前端 + CDN 图表库 | 没网就白屏 |
| **单文件 HTML（自绘 canvas）** | 双击就能用、可邮件发送、零依赖 |

### 构建指纹：页脚那个数，和构建输出是同一个

`build_ui.py` 末尾打印两行（下面是一次的真实输出）：

```
源码指纹：26bdf9e55d39   ← 页脚 __build.id 显示的就是这个
产物 sha：bc60606520ea   ← 只这一份文件的哈希，用来核对"重建是否逐字节相同"
```

两者不是一回事，用的时候别混：**产物自身的 sha 没法写进产物本身**（自指问题），
所以页脚显示的是**源码指纹** —— 每个输入文件的"名字+内容哈希"串起来再哈希一次，
只跟源码内容有关、与构建时间无关。拿页脚去核对"是不是同一版"，要对的是**源码指纹**那一行。

指纹清单必须覆盖**全部**输入，少一个都会让"指纹相同 ⇒ 内容相同"失效：
`ui/app.html` 一度漏在清单外，结果改了模板（连带弹窗里的那些数字）指纹原地不动。
现在 `collect()` 把模板也记进 manifest，"改模板 → 指纹变 → 还原 → 指纹回到原值"
三条都已实测。

### 窄窗口：工具栏会自动换行

"六个标签 ＋ 修正列名笔误 ＋ 五个导出按钮（含质量报告）"这一行的自然宽度实测
**991 px**（2026-10-02 加重量的：五个标签时是 876 px，第六个「IsoplotR 谐和图」
是个长文案，多出 115 px），而右栏能用的宽度实测恒为 **视口 − 372 px**
（1600 / 1440 / 1366 三点一致）。所以不换行需要视口 ≥ 991 + 372 = **1363 px**。

**断点因此从 1300 px 上调到 1420 px。** 原因是基础样式是
`flex-wrap: nowrap` + `overflow-x: auto`：不换行时超出就**横向裁掉**。
五个标签时 876 + 372 = 1248 < 1300，恰好没有坏带；加上第六个标签后 1363 > 1300，
于是 1301–1362 px 这一段会正好切掉最右边的「质量报告」（这一版的主按钮）。
1420 留约 57 px 余量（与上一版 1300 对 1248 留 52 px 的松紧相当），
且 1440 宽的窗口仍是单行（余 77 px）。

这个数**必须实测**，不能估：`G:/_isohtml/mkinject.py` 有一个 `measure` 用例，
它把 `.tabs` 设成 `width:max-content` 再读实际宽度，与视口无关；
`G:/_isohtml/measure_tabrow.py` 在此基础上把"每个视口下是否溢出（被裁）"
一并打出来 —— **溢出量才是判据**（别用"按钮落在几行"当判据：标签按钮与
导出按钮高度不同，它们在单行里也永远分属两个 top 值）。
改按钮文案或增删按钮后要重新量一次并更新断点。

`build_ui.py` 自己也会拦几类错：占位符残留、模块漏打、内容被
`</script>` 提前截断、顶层重名（见下），以及每个模块是不是真的落在**自己的**
script 块里。

## 两层判据：为什么不能只看"跟桌面版差多少"

`exp` / `log` 各语言实现允许差约 1 ULP（IEEE-754 不要求它们正确舍入），
所以"用宿主 libm 还能逐位相等"是不可能的事。实测：

| 探针 | V8 (`Math.exp`) | glibc |
|---|---|---|
| 786 个真实自变量里的 `exp` | 75 个不是正确舍入（9.5%） | 4 个 |
| 202 个真实自变量里的 `log` | 10 个（5.0%） | 3 个 |

移植时这条差异真实地咬了一口：`Age76Pb` 那一列老是差 1 ULP，一开始误当成移植 bug。
所以网页版**自己实现了正确舍入的 exp/log**：

| 侧 | 实现 | 精度 |
|---|---|---|
| JS | `src/fp.js`，双倍-双倍（~106 bit）算法 | 正确舍入 |
| Python | `pycr.py`，`decimal` at 60 digits | 正确舍入 |

两侧先在一次大范围抽查里逐位一致（44109 个 `exp` 点、21162 个 `log` 点，
覆盖常规值、极端值与次正规数），随后把其中 7608 + 2509 个自变量固化进
`src/fp_case.json`，`test_fp.js` 每次都重跑一遍 —— 也就是说这条一致性是可以被
持续验证的，不只是一次性抽查。于是每个测试套件都跑**两条判据**：

1. **对"正确舍入参考值"逐位相同** —— 这验的是*移植本身*有没有错；
2. **对"真实桌面版输出"只看偏差量** —— 这量的是*与桌面版实际差多少*，
   并要求差异只能落在含 exp/log 的列上、相对偏差 < 1e-9。

实测最大相对偏差 **8.6e-11**，只出现在第 24/26/27/28 列（都是 exp/log 列）。
副产品：网页版的结果**不再依赖运行平台** —— 同一批数据在任何浏览器、
任何系统上都是同一串数字。

## Agilent 链路的判据：双格式一致性

`test_agilent.js`（9 项）只验**读取器本身**（列名、缺列补齐、报错），
它跑绿并不代表从界面点下去能出结果 —— 中间还可能接错读取器。
所以另立一套 `test_agilent_e2e.js`（20 项），判据设计成这样：

**判据一：双格式一致性（不需要 Python 侧参考）**

把**同一组计数率**分别写成 Thermo 格式和 Agilent 格式，跑完整条链，要求
`Mean_Cps.csv` / `result_all.csv` 逐字节相同、年龄表逐位相同。
这条判据的好处是不依赖任何外部参考值 —— 两边都是自己算的，对不上就一定是其中一条路径错了。

**判据二：数值可反推**

测试数据直接由 **485 Ma 的比值**反算构造（`net = U_NET * Cal_age(485)` 一族），
所以年龄必须回到 485 Ma 附近。实测最大偏差 **0.018 Ma** —— 把"不是 NaN"升级成了
"数值真的对"。

**判据三：反向哨兵**

在 Agilent 模式下丢 Thermo 文件，必须**全部解析失败**；切回 Thermo 后必须恢复正常。
这一条专门盯"仪器切换到底有没有生效"：如果两条路径其实调的是同一个读取器，
这个断言会立刻失败。页面自检里也放了同一条。

写这套测试时撞到的三件事，其中第一件同时也是**原实现的一个真实边界**：

- **积分窗口的首点**：信号切片是 `[int(s0/ti), int(s1/ti))`。如果采样步长 > 1 s，
  `int(s0/ti)` 会落在平台**前一个点**上，而那个点的净信号恰为 0 →
  0/0 → 整列出 NaN。用步长 ≤ 1 s 的数据即可避开。
- **2σ 滤波退化**：`|x-avg| < 2*sd` 在**完全恒定**的段上退化成 `0 < 0`，
  所有点都被丢掉 → NaN。合成数据要带一点点周期抖动。
- **`divArr()` 的防呆边界**：标量误用会 `throw`，但 `0/0` 是合法的 NaN，不抛异常 ——
  所以上面那类问题只能靠数值断言抓，不能指望报错。

## Thermo 兼容读取：让真实文件能读进来，但绝不静默读错

严格路径把表头钉死在**原始第 14 行**，列名按**精确相等**匹配且不 `strip`。
真实仪器导出的 CSV 常常不是这样：多导几行元信息、表头行位置不同、
列名带单位或括号或大小写不一。原本这类文件会直接读不了。

现在多了一条**兼容路径**，做法是"先探测，不盲读"：扫前 40 行，找一个能
**同时**匹配 Time 与 206/207/238 的行当表头，数据起点取该行 +2 行。

为了让"放宽"不至于读到别的仪器的文件，加了三道收紧，每一条都对应一个真实风险：

| 收紧 | 防的是什么 |
|---|---|
| 表头行必须**同时**匹配 Time 和 206/207/238 | 数据行不可能满足（第一格是秒数，匹配不上 Time 的等价写法），所以不会把数据行当表头 |
| 归一化时**不剥掉** `#` | 被注释掉的表头行仍然认不出来 —— 与 Python 的行为一致，该报错还是报错 |
| 变体匹配要求**质量数 + 元素字母同时命中**；Time 列只接受与标准列名等价的写法（不接受 `时间`） | 见下 |

第三条是被测试逼出来的。第一版放宽成"列名含质量数即可"，结果
**Thermo 读取器能读 Agilent 文件了**：真实 Agilent 表头是
`时间 [s] / 202 / 204Pb / 206Pb / 207Pb / 208Pb / 232Th / 238U`，
后六列确实带元素字母，所以"质量数 + 元素字母"还不够。
真正的判别器是那个**中文时间列**（写死在 Agilent 的 `isoname` 里）。
`test_agilent_e2e.js` 的反向哨兵"Agilent 模式下丢 Thermo 文件必须全部失败"
当场从 20/20 掉到 19/20 抓到了这个问题 —— 如果不加这道收紧，
"仪器选错"会从一声响亮的失败变成一次**静默误读**，而那是最坏的一类 bug。

判据是**双格式自一致**（`test_thermo_compat.js`，47 项）：同一组数字分别写成
标准写法与各种变体写法，读回来必须**逐位相同**；变体必须在严格模式下**失败**；
标准文件必须报 `mode: 'strict'`；本来就严格可读的（只是列序不同）两种模式结果相同；
真正读不了的文件两种模式都失败。变体覆盖：带单位后缀、全小写、带 padding、
表头被注释行推下去一行、7 行元信息、20 行元信息、中间夹一个空行；
反面用例包括 Agilent 的纯数字列名与**真实** Agilent 表头。

**对"逐位相同"这条承诺的影响**：标准格式文件走的仍然是原来那条路径，
没动一行；兼容路径只解决"能不能读进来"，读进来之后的数值链条完全一样。
文件列表里会给走兼容路径的文件打「兼容」标记（悬停看具体差异），
底下还有一行摘要，报告的第 5 节也会汇总。

## 内置的真实示例数据

左栏「载入示例：真实锡石数据」那一批，是**真的**：49 个 Thermo iCAP Qtegra 导出
（锡石 LA-ICP-MS U-Pb，**同一次连续会话**：前后各夹一个标样 `SRM 612`），
一件不落地内嵌进单文件里。

**为什么要内嵌真数据。** 合成示例只能证明"版面是通的"，证明不了"真数据能跑"。
真数据里有信号弱到快贴地的点、有信号段前面挂着一个单点噪声尖峰的行 ——
这些才是使用现场每天都会遇到的东西，而且**任何设想都替代不了**：
`sample_25.csv` 那个尖峰把积分窗口带偏、整行比值算成 NaN，就是跑真数据跑出来的，
不是设计出来的 —— 这条也正是后来给窗口识别加"噪声尖峰过滤"的起因
（见 `src/window.js` 的 `minSig`）。

**为什么是 49 个而不是源目录里的 50 个。** 源目录里有一个文件是**越界的采集**：
它是全批唯一采集日期不在主会话那天的，总行数也与全批差一个档

对不上就报错不落盘 —— 宁可构建失败，也不要静默少一个文件。

stdAge=158.2, fracStd=AY-4, nistStd=SRM 612, method=1, algo=avg, excess=3`）

（极差 0.012 Ma）；`multi` 取 3/4/6/10 也稳。

**量出来的结果与公开文献对得上。** 标样 `AY-4` 出 **157.06 ± 1.39 Ma（2σ，MSWD 0.70，
15/15 点）**；两个公开发表的 ID-TIMS 值是 Yuan et al. (2011) 158.2 ± 0.4 Ma 与
Carr et al. (2020) 151.9 ± 2.2 Ma —— 它们本身相差 6.3 Ma（AY-4 的"真值"在文献里
就有争议，源方法文档花了一整节讲这件事），所以判据取两者中点 155.05 ± 5 Ma。
剔除那个越界文件前后，这个数**一位都没变** —— 它属于另一个标样、另一次会话，
本来就不进 AY-4 的统计。

> **误差口径要跟着数字走。** 这个 1.39 是 **2σ**；质量报告里的标样表印的是
> **1σ 内部标准误**（同一个数是 0.7）。两处都印数字却不印口径，读的人会以为
> 程序在两个地方算出了不同的结果。所以 `stdMeasured` 把 `sigma: '2σ'` 一起存下来，
> 界面日志、`docs/index.html`、本文件都从它引用，不另抄一份。

**它自己的毛病也一并登记。** `flaws` 里是真管线量出来的三样东西：
积分窗口定不出来、比值列整行 NaN 的文件 **0 个**（给窗口识别加噪声尖峰过滤之前是
4 个：`sample_10/23/25/40.csv`，成因是信号段前面那个宽度仅 1 个采样点的尖峰被当成了
信号段，窗口塌缩到零点几秒、甚至 s0 > s1 —— 过滤规则与对照用例见 `src/window.js`
与 `test_window.js`），16 个净 ²⁰⁶Pb 低于本批中位数一半的文件，以及信号最弱的那一个
（`sample_30.csv`，净 ²⁰⁶Pb ≈ 150 cps）。**只报不拦**：真数据就是这样，质量报告会把
不合格的点剔除，而不是拿它们去污染加权平均 —— 所以"参与平均的点数"少于"文件数"
是可能的，也是**对的**。
界面上凡是要说"这批有多少个文件 / 有几个是坏的"，都从 `flaws` 与 `files` 现读，
不在 HTML 里抄第二份（那个手写的数已经过期过一次）。

**三道门禁**（`test_demo_real.js`，22 项，CI 每次重跑）：

1. **脱敏门禁** —— 真解压后逐个查样品名，必须全落在 `^(SRM 612|AY-4|S-\d\d)$`
   白名单内（测试里**不允许写真实代号**，否则门禁就成摆设）；
2. **字节门禁** —— 重算明文长度与 sha256，与产物声明的一致；
3. **地质门禁** —— 跑完整管线，标样年龄必须落进两个公开值的中点 ±5 Ma，MSWD < 2，
   且**产物里声明的 `stdMeasured` 必须等于这次实测值**（这条最重要：正文引的就是它，
   不钉住的话文档会拿着过期数字往外说而没人发现）。

重跑生成器：

```bash

python webgui/make_real_demo.py --src "<原始导出目录>" --check   # 只核对现有产物是否还一致
```

## 质量报告：一批数据好不好，一页看完

**形式是"导出独立 HTML 文件"，不是页面里的一个标签页。**
理由：报告是拿给别人看的（导师、评审、合作者、存档），对方不该需要装这个软件、
也不该需要联网。所以生成的是一份**单文件、内联样式与内联 SVG、零外部依赖**的 HTML，
双击就能开，`Ctrl+P` 就能存成 PDF。

七个章节：①概况 ②这次用的参数 ③标样 QC ④样品结果汇总 ⑤异常与警告
⑥判据 ⑦这份报告不做什么、以及已知的口径问题。

### 统计怎么算

按 Wendt & Carl (1991) / Isoplot 的定义：`w=1/σ²`、`μ=Σwx/Σw`、
`se=1/√Σw`、`MSWD = Σ((x−μ)/σ)²/(n−1)`，`MSWD>1` 时外部误差 `se·√MSWD`。

**年龄表里的 `2s` 列是 2σ，内部必须折成 1σ。** 忘了折的话 MSWD 会小 4 倍、
误差会小 2 倍 —— 数字看着更"漂亮"，但全是假的。`test_qc.js` 专门钉住这一条
（判据不是拿 `qcWavg` 自己比回去，而是照着定义在测试里另写一遍手算值）。

### 判据阈值：给默认值 + 说清为什么 + 界面可改

| 判据 | 默认 | 出处 / 为什么 |
|---|---|---|
| 标样相对偏差 | ≤ 2% | 常见做法是要求标样再现性优于 2%，**但不同实验室要求不同，请按你们的惯例改** |
| MSWD | ≤ 1+2·√(2/(n−1)) | MSWD 期望值为 1，在"单一年龄母体"假设下服从 χ²/(n−1)，其取样分布标准差 ≈ √(2/(n−1))，故取 1+2σ（约 95%） |
| 单点 2s 相对误差 | ≤ 10% | 经验值。相对误差大往往意味着 ²⁰⁶Pb 计数低或积分窗口没取好 |
| 离群判据 \|z\| | ≤ 3 | 常规提示线。**它只是提示，不是自动剔除** |

这四条**都是经验判据，不是原程序的规定**。界面上可以改，改过的会在报告里标「已改」。

### 判定必须带理由，不能只给颜色

真实数据里会出现**标样相对偏差 0.0000%、但内部 MSWD 高达 325** 的情况
（`age_case.json` 里的 MAD-NEW 就是这样：整批再现性不差，点与点之间却散得离谱）。
只印一个黄色方块，读的人只会以为"没问题"。

所以每个 warn/bad 都在表格里把原因列出来（名义上是哪条判据、量是多少、超了多少、
可能是什么原因），结论区也会把标样的第一条原因搬进去。`test_qc.js` 里有一条
不变量盯着这件事：**凡是判了 warn/bad 的，必须有理由**，否则报告里就会出现
"看不出为什么"的红黄格子。

### 不静默做错事

- **列映射**：校正后年龄的实际列号按校正方式分派（1/2/3 法 → ²⁰⁷Pb/²³⁵U 在第 27 列、
  ²⁰⁶Pb/²³⁸U 在第 29 列；4 法 → ²⁰⁶Pb/²³⁸U 在第 27 列、²⁰⁸Pb/²³²Th 在第 29 列；
  0 法没有校正列）。表头自检会发现列错位并在报告里报出来。
  另外有两列表头的写法与内容不一致（沿用自原程序）：第 17 列表头写 `Age` 而数据是分隔线、
  第 26 列表头写 `…Corr. Age(Ma)` 而数据是备注。报告里按实际列位置取数并写明。
- **选不到就说明**：界面选的年龄种类在该校正方式下没有校正列时，自动退到未校正列，
  并在日志与报告里都写一句，不静默换列。
- **不可信输入全部转义**：样品名来自用户的文件，完全可能出现 `<` `>` `"`。
  `test_report.js` 用真恶意串喂进去，验的是输出里只有转义形式。
- **不做假的**：报告里没有任何外部链接与脚本；缺值写成 `—` 而不是空单元格；
  离群点只列出来，**不替用户剔除**。
- **示例数据自曝身份**：左栏有两个示例入口，出处不同，声明也不同 ——
  「真实锡石数据」是 49 个真实导出，报告顶部是**蓝色**声明（说明脱敏做了哪三件事、
  数字是真算的，但**不构成对任何矿床的年龄结论**）；
  「合成数据」是人为拼的计数，比值之间不满足 U-Pb 体系关系，跑出来的偏差与 MSWD
  必然难看，报告顶部是**红色**声明（这些判定只演示版面、**不能当结果引用**）。
  `state.demo` 因此是 `false | 'real' | 'syn'` 三态 —— 两种数据的免责声明意思相反，
  用一个布尔量分开是错的。

报告里反复写明的一点：**加权平均、MSWD 与所有判据阈值都是网页版新增的，
不是桌面版 Isoclock 的输出**（原程序只输出逐点年龄，从不做归组统计），
引用时请区别对待。

### 怎么验

`test_report.js`（50 项）不引浏览器、不引 DOM —— `ui/report.js` 是纯函数，
在 Node 里把源码跑起来就能验：单文件骨架（无外链、无 `<script>`、有打印样式）、
七个章节齐、`PARAM_DOC` / `THRESHOLD_DOC` 每项都印进了报告、行数与数据一致、
每条 warn/bad 的"为什么"都印出来了、没有 `undefined` / `[object Object]` /
孤立 `NaN` 单元格、恶意样品名被转义、SVG 点数与数据一致、两次调用逐字节相同、
退化输入（空数据 / 没有构建信息）不崩。

排版另用无头 Edge 实拍：`G:/_isohtml/report_e2e.html` 真的依次点
「载入示例数据 → 开始计算 → 质量报告」，把 iframe 里的 `URL.createObjectURL`
换掉以扣下 Blob（**不改被测代码**），再把报告摊开截图。

有一条路子**试过但不行，别再试**：让无头 Edge 自己去"下载"那份报告。
`--headless=new` 下 `<a download>` + blob 不会落盘（下载目录里 0 个文件），
而且浏览器进程会**挂住不退出**，得手动 `taskkill`。要拿报告原文就用上面那套拦截法。

## 单文件构建里踩的坑：模块不能合并进同一个 script 块

`src/` 下的模块是"平铺式脚本"：顶层直接写 `const` / `function`，靠 `window.DS_*` 交接。
这种写法在 Node 下没问题（`test_*.js` 每读一个文件就是一次独立的
`vm.runInContext`，各自一个脚本作用域）。但**把 7 个模块拼进一个 script 块就会出事**：

```
函数声明会被提到脚本最前面统一实例化，同名的只留最后一个。
pipeline.js 与 age.js 都声明了 `function attach`，合并后
const DS_PIPELINE = { attach, ... } 里装进去的其实是 age.js 那个 attach
  -> PL.attach(...) 把参数写进了 age.js 的内部对象
  -> pipeline 自己的 thermoLoad 一直是 undefined
  -> 一跑就是 "P.thermoLoad is not a function"
```

这个 bug 很隐蔽：所有内容都在文件里、`DS_PIPELINE` 的键一个不少、
拿数字去调 `attach` 也不报错（两个实现都是 `Object.assign(X, mods)`，
返回 `undefined`）。它只在"真的有人调用 `PL.attach` 之后又去用管线"时才暴露。

现在有两道防线：

- `build_ui.py`：一个模块一个 `<script>`，并检查顶层声明名有没有跨模块重名；
  重名必须写进 `TOP_LEVEL_DUP_OK` 并**写明理由**才能通过（目前两处：`attach`、`pyInt`）；
  同时会把"合并后确实会互相覆盖"的那几个函数源码打印出来给人看。
- `ui/selftest.js` 里两条哨兵：`PL.attach !== AGE.attach`，以及"给管线塞一个假
  `thermoLoad`，确认它真的被调用到"。

## 让字节比对成立的两个细节

### 1. 浮点的**文字表示**也必须一致

Python `csv.writer` 对 float 调 `str()`，也就是 `repr`（最短往返表示），
但它的排版规则和 JS 的 `String(x)` 不同：

| 值 | Python `repr` | JS `String` |
|---|---|---|
| `1e-5` | `'1e-05'` | `'0.00001'` |
| `1e16` | `'1e+16'` | `'10000000000000000'` |
| `5.0` | `'5.0'` | `'5'` |
| `NaN` | `'nan'` | `'NaN'` |

`src/report.js` 先用 JS 取最短往返数字串（这一步两边算法等价），再按 CPython
`PyOS_double_to_string` 的规则重新排版：`decpt > 16` 或 `decpt <= -4` 走指数
形式（指数至少两位），否则定点、整数值补 `.0`。38 个探针逐字通过。

### 2. JS 没有 int/float 之分，而 Python 有

`result_all.csv` 的 `No.` 列在 Python 里是 `int`，`str(1)` 得到 `'1'`；
JS 只有一种 `number`，直接按浮点渲染就成了 `'1.0'` —— 这是实测抓到的
**唯一一处字节差异**（`src/math.js` 里 `tagInt()`）。

**不能用「值是不是整数」去猜**：浮点列里完全可能出现 `3000.0` 这种值，
Python 会照旧打印 `'3000.0'`，猜法会把它错印成 `'3000'`。

## 顺带查出来的四件事（都是读代码 + 实测确认的）

### 1. `Isoclock2.0.py` 里有一段注释把仪器编号写反了

文件第 120-125 行的注释说：

```
ele == 0  Element 类（列名硬编码，跳过 13 行）
ele == 2  Thermo （列名全部按原名，跳过 7 行）
```

**实际是反的。** 依据（三处互相印证）：

| 证据 | 位置 |
|---|---|
| `Radiobutton(text="Thermo", value=0)` / `value=2` 是 Element | 3388-3390 |
| `samplelist()` 按 `ele` 分派，注释里写明 `ele=0 → Thermo` | 3371-3379 |
| `instructure0`（ele=0）扫描 `*.csv`、**不弹 LIST 对话框**；`instructure2`（ele=2）扫描 `.FIN`/`.FIN2`、弹 `askopenfilename` 要 LIST 文件 | 1837-1839 / 2381-2389 |

Thermo「不需要 LIST 文件」正与说明书一致。所以 **ele=0 = Thermo，走 `loaddata` 的
mode 0（skiprows=13、列名 `Time/202Hg/204Pb/...`）**。这段注释会误导后续维护者。

### 2. 样品名的两个来源：Thermo 读文件头，Agilent 读**清单**

两台仪器的样品名根本不是同一套规则，这是使用上最容易踩的地方。

**Thermo**（`instructure0` 1928-1937 行）：读第一行 → 取第 0 个 CSV 字段 → 按 `:` 切开取 `[0]`。

**这是使用上的硬规则**：冒号之前的整段都是样品名。

| 第一行写成 | 得到的样品名 | 后果 |
|---|---|---|
| `91500: zircon standard` | `91500` | 正确，能匹配标样表 |
| `Sample MAD-NEW-1: note` | `Sample MAD-NEW-1` | **匹配不上** `MAD-NEW-1` |
| `NIST610`（没有冒号） | `NIST610` | 可用 |
| `"quoted, with comma": note` | `quoted, with comma` | 需要按 CSV 规则解析引号 |

**Agilent**（`instructure1`）：**完全不读文件头**，而是拿
`Sampleslist1[name.split('.')[0]]` 去一张外部表里查 —— 键是**文件名第一个点之前**的全部内容。

| 文件名 | 查表用的键 |
|---|---|
| `MAD-NEW.csv` | `MAD-NEW` |
| `MAD-NEW.1.csv` | `MAD-NEW` |
| `91500_2.csv` | `91500_2` |

桌面版这张表是 `askopenfilename` 选的 **Excel `LIST`**（xlrd）。网页版不带 Excel 解析器，
改成**两列 CSV/TSV**（第一列 = 键，第二列 = 样品名，自动识别逗号/制表符分隔，
不跳过表头，允许带引号）。

清单里查不到时，**两台仪器的兜底不能共用一条规则**：

| 仪器 | 兜底取法 | 为什么 |
|---|---|---|
| Thermo | 读**文件第一行**（与桌面版一致） | 第一行本来就是样品名 |
| Agilent | 取**文件名第一个点之前**（即清单键的规则） | 前几行是仪器元信息，**所有文件一模一样**；照 Thermo 的规则读会把所有样品塌成同一个名字，年龄层再把它们并成一个样品，**错得毫无提示** |

名字的来源会在文件列表里逐行标出（`清单` / `第一行` / `文件名`），避免看着对、
实际名字对不上。`test_agilent_e2e.js` 里专门有一条断言盯"无清单时这些名字必须两两不同"。

样品名必须与软件里填的标样名**完全一致**，否则标样会被当成普通样品。

### 3. 背景窗口的默认值没有可靠出处

`bcg_from` / `bcg_to` 只在 `setbcg_multi()` 里从界面输入框赋值（3251-3252），
而那两个输入框是空的 `StringVar()`。`main()` 里给了 `bcg = [1, 5, 8]`（2913），
另一处又写着注释掉的 `#bcg_from=3 / #bcg_to=10 / #multi=8`（2909-2911）。

**即默认值不确定**（1/5/8 还是 3/10/8）。所以网页版把它们做成**可编辑输入**，
默认 **8 / 16 / 4**，以便和桌面版对齐任意一组设置 —— 不做猜测。
（点"载入示例数据"时脚本会改成 1 / 5 / 8，因为那份合成数据的信号落在 7~17 s。）

### 4. 外挂误差 Ɛ：只进误差、不进年龄，而且口径有三处不齐

桌面版界面上这一格写作 **`Ɛ(%)`**（`Isoclock2.0.py` 第 3484 行的 `Label`），
源码里是 `excess_V = float(var5.get())/100`（245 / 854 行），
**默认 `var5.set(3)` → 3%**（3436-3442 行）。
（网页版早先把它默认成了 5，现在改回 3，与桌面版一致。）

**它是什么**：除"数计数"本身的统计波动之外，还会有的一部分**额外分散** ——
剥蚀效率波动、气溶胶传输不均、基体差异、标样与样品不匹配、软件拟合残差等。
只用计数误差会**低估**不确定度，Ɛ 就是用来补这一块的。

**它怎么用**：以**平方和**（正交相加）并进每一个年龄的相对误差：

```
年龄相对误差 = sqrt( 内部相对误差² + Ɛ² )
```

依据是第 397 行（²⁰⁶Pb/²³⁸U 年龄）：

```python
(sqrt(pow(date_all[3][i]/(date_all[2][i]*f206_238),2) + excess_V*excess_V)) \
    * (log(abs(date_all[2][i]*f206_238+1))/(0.000000000155125)/1000000)
```

`date_all[3][i]` 是这个比值自身的 2s，除以比值本身就是**相对误差**。
399 / 401 行的 ²⁰⁷Pb/²³⁵U 与 ²⁰⁸Pb/²³²Th 年龄用的是同一个模板。

**它不影响年龄值**。年龄是 `ln(比值+1)/λ`，Ɛ 只出现在误差项里。
把 Ɛ 从 3 改到 30，年龄一个数都不变，所有 `±` 跟着放大。
唯一跟着动的是 **`rho`（第 41 列）**，它的公式里也用了 Ɛ。

三处口径并存，用的时候心里得有数：

| 现象 | 原因 |
|---|---|
| Ɛ 算 1σ 还是 2σ 说不清 | 内部相对误差用的是**比值的 2s（即 2σ）**，而 Ɛ 是直接与它平方相加 —— 相当于按 2σ 同量级对待。没有实测过 Ɛ 的置信水平，这里就是混着用的，报出去的不确定度是几 σ 要自己心里有数 |
| ²⁰⁷Pb/²⁰⁶Pb 年龄（第 24 列）的误差**不含 Ɛ** | 它是 `solve76(R76+d1) − solve76(R76)`，只由该比值自身的误差传播，没有进 `sqrt(… + excess_V²)`。所以同一行里四个年龄的误差口径**并不一致**，横向比较要小心 |
| Ɛ 调大 → **MSWD 变小** | 每个点的误差都变大，点与点之间就显得更一致了。当 Ɛ 远大于内部误差时各点误差趋于同一比例，MSWD 会趋近 0，加权平均退化成普通平均。**不要用调 Ɛ 的办法去"改善"一致性** —— 那是靠灌水不确定度换来的表面一致 |

网页版在④那一格旁边把这些都写出来了（界面上直接可读），出报告时也会把当次用的 Ɛ
连同其它参数一起记进参数快照，免得事后不知道那份报告是按哪个 Ɛ 算的。

## 移植中踩到的三个坑（都靠实测定位，不是推测）

### 1. NumPy 的求和不是左到右累加

`np.sum / mean / std / average / nanmean / nanstd` 全部走**成对求和**
（pairwise summation）：分块 128、8 路展开累加器、超过 128 再二分递归，切点对齐到 8 的倍数。

朴素累加与它的相对差实测可达 **1.3e-15** —— 足以让末位不同的数值进入论文表格。
`src/math.js` 里 `pwSum()` 逐行复刻了 `numpy/core/src/umath/loops.c.src` 的
`pairwise_sum_DOUBLE`，连 `n2 -= n2 % 8` 都一致。

### 2. `np.nanstd` 会把被掩位置"减完均值再打回 0"

这是最隐蔽的一处。`numpy/lib/nanfunctions.py::nanvar` 的实际顺序是：

```python
arr, mask = _replace_nan(a, 0)      # NaN -> 0
cnt = sum(~mask)
avg = sum(arr) / cnt                # 在原长数组上求和
np.subtract(arr, avg, out=arr)      # 全部位置都减 avg
arr = _copyto(arr, 0, mask)         # ★ 被掩位置重置回 0
var = sum(arr*arr) / cnt            # 仍在原长数组上求和
```

第 5 行是关键：被掩位置对平方和贡献 **0**，不是 `(0-avg)²`。
少这一步实测相对差 **4e-3**；改成"压缩有效子集再算"能降到 0.5 ULP 但仍不逐位相等
（数组长度变了，成对求和的分块结构就变了）。

顺带：`Series.std()` 是 **ddof=1**，`numpy.std` 默认 ddof=0 —— 混用会整体偏一点。

### 3. 标量除法会静默产出 NaN

`net.pb204` 是标量，Python 里写 `n8 / pb204` 合法，JS 里 `a[i]/b[i]` 得到一片 NaN
**且不报错**。现在 `divArr()` 收到标量会直接 `throw`，逐元素除法必须显式用 `divScalar()`。

## 年龄层里踩的两个坑

### 1. pandas 的 `series[label]` 在匹配 1 行时返回**标量**

实测 pandas 1.5.3（与索引是否唯一无关）：

| 匹配行数 | 返回 | 于是 `date_all[14][s][:]` |
|---|---|---|
| 0 | 抛 `KeyError` | 被外层 `except` 吞掉 → 系数归零 |
| 1 | **标量 `numpy.float64`** | 抛 `IndexError: invalid index to scalar variable` → 同样被吞掉 |
| ≥2 | `Series` | 正常 |

所以**整批数据里只插了一个 NIST 标样时，微量元素系数会静默变成 0**。
`age.js` 里 `coefficients()` 照抄了这个行为（`idx.length < 2` 就返回 `[0,0,0]`），
界面也会提示。这是原实现的一个真实用户陷阱，不是移植的疏漏。

### 2. 线性法表格里的误差项用的是**校正后**的比值

`Age_Calculate()` 里 method 1 那两个局部变量 `Corr_7_5_age_erro` /
`Corr_6_8_age_erro` 是用**未校正**比值算的，但它们**从不进入表格**；
表格里第 26/27/29 列用的是校正后的 `R75` / `R68`。
照着局部变量写就会差 20 格 —— 这是 `test_age.js` 抓出来的。

### 图上的点应该是**样品**，不是标样

下拉里默认那一条是「全部样品（不含标样，N 个可用点）」，标样另有单独的分组，
标签写着「标样（QC 用，不是样品年龄）」。理由是内置这批数据**一个文件一个测点**：
49 个文件 = 32 个样品（各 1 点）+ 标样 AY-4 的 15 个 + 外标 SRM 612 的 2 个
（这张清单由 `test_isoplotr.js` 的 §G 钉住）。只按点数排序会把 AY-4 顶到第一位，
而它是 QC 样 —— 年龄要跟②里填的真值比，**不是待测样品的年龄**。

这个错**只能靠"知道这些点是什么"发现**：拿 AY-4 拟合出来的数看着完全正常
（13 个近谐和点、谐和年龄 157.36 Ma、MSWD 0.021），代码拦不住、数字也拦不住。
同类事实还有一批：**单点样品拟合年龄没有意义**（IsoplotR 会直接报
`Cannot fit a straight line through these data`），这一页在点数 < 3 时会把
discordia 那三个选项禁掉并写清原因，但**不替用户删数据**。
